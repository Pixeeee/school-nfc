# Teacher roster, messages and monthly reports (1.6.0)

- The Spark teacher navigation is **Roll call · NFC · Dashboard · Messages · Settings**.
- Students default to full surname A–Z, then first name. Synchronization supplies the explicit surname, including compound surnames. Old unsynchronized names use the final word until refreshed.
- **Customize order** moves students up/down. The saved order belongs to this teacher, school and class on this phone. New students appear after the custom list in surname order. **Reset to surname A–Z** restores the default.
- Select a student tile to **Edit student** or **Delete student**. Only the advisory roster owner or subject-class creator may manage that roster; assigned subject teachers cannot edit another adviser's roster. Editing preserves the code. A changed phone requires verification and consent again.
- Delete requires confirmation and connectivity. It archives the roster record without reusing its code or removing attendance. This phone's attendance must finish syncing first. Cached authorization is invalidated after server mutations until a complete refresh succeeds.
- Editing/deleting cancels that student's unsent texts on this phone. Already handed-off messages cannot be recalled; cancellation intent prevents future retries even after callbacks or interrupted sends. Other phones should synchronize their roster before taking attendance.
- **All subject attendance records update without parent SMS.** Advisory attendance and adviser Out retain texting. Both On time and Late students have green tiles, with status text distinguishing them. Existing unsent subject texts are cancelled when the updated queue worker runs.
- In **Settings → Teacher profile → Customize parent messages**, configure advisory attendance and Out templates. Supported placeholders: `{{studentName}}`, `{{studentCode}}`, `{{sectionName}}`, `{{attendanceStatus}}`, `{{eventDate}}`, `{{eventTime}}`. Student, status, date and time are mandatory. Username and school are appended automatically. Blank templates restore standard wording. Save online; the validated teacher-specific cache works offline. Existing queued texts keep their original wording.
- **Dashboard** selects a month and optionally a class/subject. It shows On time, Late, Absent and Recorded totals, plus each student's counts. Latest status per student/class/subject/day wins; repeated corrections do not add days. Dismissal is excluded. Unrecorded days are not counted as absent. A student present in advisory and subject counts separately for those class sessions; this is not a unique school-day total across subjects.
- Reports contain only attendance authored by the signed-in teacher. They use synchronized Firebase records from all devices, retain archived-student history, exclude parent contacts, and explain pending local changes. They need internet. Queries are bounded to the requested month and teacher, with a composite index. More than 20,000 attendance changes in one month returns an explicit error instead of an incomplete report.
- Room migration 4→5 preserves existing students, attendance and texts while adding surname fields and durable SMS cancellation intent. No new dependency, Android permission, Firebase Function or billing plan is introduced.

Verification: React controls/helper tests, portal integration against Firebase Auth/Firestore emulators, Firestore ownership/field rules tests, Android JVM tests, actual Room migration and attendance/queue tests on an Android 13 emulator, and 360px UI inspection with a labeled local simulation of the native bridge. Physical SIM/carrier delivery is not exercised by these tests.
